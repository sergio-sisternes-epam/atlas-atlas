## Decision

Atlas plays in **storage and behaviour**. It defines how knowledge may exist, be compiled, branched, mounted, and contributed. It does not play in managed retrieval-as-a-product.

## Rationale

The name pin already scoped Atlas to compiled modular project knowledge. The 2026-08-27 framing locks the same idea for multi-team SDLC. Competing as a memory API would pull the roadmap toward extractors and hosted indexes and away from git contribution.

## Alternatives considered

- Agent memory layer (Mem0-class) — terminated; see `atlas-project/wrong-path-agent-memory-layer/exit-wrong-comparison.md`.
- Enterprise search appliance — rejected as identity; accepted only as an optional projector.

## Consequences

Feature requests are admitted if they strengthen SoR files, compile, work hubs, mesh, or PR contribution. They are refused if they only make sense on a memory-layer leaderboard.
