## Content

### Thesis (terminated)

Atlas is an agent memory substrate. The 2026 market for that job is Mem0 (hybrid extract-retrieve), Zep/Graphiti (temporal knowledge graph), Letta (memory OS), Cognee (document-to-graph), plus LangMem and Supermemory. File-based cousins (Basic Memory, ByteRover, DiffMem) are closer architecturally but still sit in the same “give the agent memory” category.

The first evaluation therefore built a feature matrix on extraction, temporal validity, LongMemEval scores, MCP, and managed hosting.

### Why it felt reasonable

Atlas pages include experience, decision, lesson, recipe. Those words overlap episodic / semantic / procedural memory jargon. The skill description says “durable knowledge stores” and “skill process memory.” Online writing in 2026 is dominated by memory-layer vendor comparisons, so the search space pulled the evaluation there.

### Why it is not current reality

The locked objective is a **modular git-based knowledge system for SDLC teams**, with Microsoft products as enterprise *realization* of the same blueprint. Memory-layer vendors optimise personalisation and fact extraction. They fail the mount-branch-PR-compile test. Scoring Atlas on their leaderboard hides the actual wedge and invites the wrong roadmap (extractors, graph databases, hosted APIs).

### Keep the branch

The mistake is cheap to repeat. Terminated knowledge answers “what Atlas is not” without forcing every later agent to rediscover the wrong set.
