## Content

These notes remain usable as market literacy. They must not drive Atlas product identity. See the terminated branch and the living comparison.

### Named systems (2026 scan)

- **Mem0** — vector-first + optional graph; auto-extraction; large community; managed + OSS. Job: personalisation.
- **Zep / Graphiti** — bi-temporal knowledge graph; `valid_at` / `invalid_at`; Graphiti OSS, Zep cloud-first after CE deprecation.
- **Letta** (ex-MemGPT) — OS-style core / recall / archival blocks the agent edits.
- **Cognee** — ECL ingest into graph + vector; many connectors; local-first friendly.
- **LangMem** — LangGraph-native semantic / episodic / procedural library.
- **Supermemory** — MCP-first managed context engine.
- **Basic Memory** — local Markdown + MCP + Obsidian; nearest file-wiki cousin.
- **ByteRover** — Domain→Topic→Subtopic markdown tree; curation before write.
- **DiffMem** — current Markdown surface, git history as time.
- **Beads** — Dolt-backed agent issue graph (`relates_to`, `supersedes`); work-queue, not a wiki.
- **Official MCP memory server** — JSONL entities; weekend-grade.

### Observations worth keeping

- Several 2026 benchmarks show graph extractors losing to markdown + grep/BM25 once retrieval budget is fixed.
- Enterprise governance (audit, retention, sensitivity) was still a gap across the memory-layer vendors.
- File-wiki tools share Atlas’s local-first bet; they lack compile, work hubs, and multi-team PR protocol.

### Do not take from this scan

Roadmap items whose only justification is “Mem0 has X.” Extraction pipelines, mandatory graph databases, and hosted memory APIs are out of vision unless they appear as optional projectors of compile-green pages.
